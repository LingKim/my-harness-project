# 文档规则

## RULE-DOC-001：人类可读内容默认使用中文

- 新建或修改的 README、OpenSpec artifacts、设计、计划、操作说明和代码注释默认使用中文。
- 代码标识符、命令、路径、协议字段、依赖名称、OpenSpec 结构关键字和没有稳定中文译名的术语保留原文。
- 第三方工具自动生成并由更新命令覆盖的文件不强制翻译，也不得手工加入项目规则。

## RULE-DOC-002：文档与事实保持同步

- 文档必须区分当前能力、计划能力和未验证假设，不把目标描述成已实现状态。
- 行为、目录、命令、依赖或架构边界变化时同步更新对应规范源和导航文档。
- 同一约束只保留一个规范源，其他文档使用链接和解释，不复制强制规则正文。

## RULE-DOC-003：交付证据保持精简和安全

- `evidence.md` 使用中文 Markdown 和项目统一模板，只保存完整命令、关键输出摘要、测试数量、可复现步骤、审查结论、未验证项与残余风险。
- 不保存完整原始终端日志、构建缓存、临时报告、无关大体积产物、凭据、token、Cookie 或隐私数据；截图和日志无法安全脱敏时不得写入仓库。
- 长 Spec Review、Experience Review 和脱敏截图按需放在 change 的 `reviews/` 与 `assets/`，由 `evidence.md` 使用相对路径链接，不预先创建空目录。
