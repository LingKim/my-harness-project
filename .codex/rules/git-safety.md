# Git 与破坏性操作安全

## RULE-GIT-001：Git 写操作按当轮明确授权

- 未经用户明确要求，不执行暂存、提交、推送、合并、变基、删除分支或创建 PR。
- “提交一下代码”只覆盖明确仓库和变更范围的 commit，不自动包含 push；既有授权不扩大到后续操作。
- dirty 工作区只暂存目标文件，提交前复核 staged diff，保护用户已有修改。

## RULE-GIT-002：避免不可恢复和范围不明的操作

- 不使用 `git reset --hard`、范围不明的 checkout/restore、递归删除或其他难以恢复操作，除非用户明确要求且目标已通过只读检查确认。
- 删除或移动材料优先使用 Git 可恢复的范围明确操作；发生删除时说明目标和恢复方式。
- 不把未解析变量、宽泛 glob、仓库根目录或用户目录作为破坏性命令目标。
