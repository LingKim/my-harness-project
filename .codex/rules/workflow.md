# OpenSpec 与实现工作流

## RULE-WF-001：非平凡行为规格先行

- 新功能、行为变化、架构调整、跨文件修复和治理契约变化必须先探索需求并建立 OpenSpec change。
- proposal、specs、design 和 tasks 必须完整，且在用户确认规格前不得进入实现。
- 纯文案、注释和无行为变化的机械格式化可以直接处理，但仍需验证实际差异。

## RULE-WF-002：实现按小任务和证据推进

- 每个任务必须说明目标文件、预期结果和验证方式；有依赖的任务串行，互不依赖且不争用文件的任务才可并行。
- 能自动化的行为遵循 RED → GREEN → REFACTOR；实现揭示规格错误时先更新 artifacts 再继续。
- 每完成一个 OpenSpec task 立即更新 checkbox，状态不能只留在聊天记录。

## RULE-WF-003：验证、同步和归档有明确门禁

- 实现完成后检查规格符合性、回归、安全、可维护性、文档一致性和无关改动。
- 只有 tasks 全部完成、验证通过且 delta/main specs 同步后才可归档。
- 实际命令、结果和未验证项必须如实报告；网络、权限或环境失败不能伪装成规格失败或成功。

## RULE-WF-004：重要 change 持久化交付证据

- 业务功能、行为变化、跨仓库、API、数据库、安全、架构和治理行为 change 在自身根目录维护 `evidence.md`；纯文案、机械格式化和只读探索可以豁免，但必须如实说明适用性。
- 主 Agent 使用 `docs/templates/openspec-change-evidence.md` 汇总开发、QA、Spec Review 与 Experience Review 的真实输出；长报告和截图按需保存到 change 的 `reviews/` 与 `assets/`。
- 审查或最终验证后又修改覆盖范围内的实现、测试或规格时，旧证据必须标记为已失效，并重跑受影响验证或记录不重跑的具体依据。
- 归档前检查全部失败、阻塞、未运行、规格偏差、体验问题和残余风险；存在未解决的阻断问题时不得建议归档。

## RULE-WF-005：单人全栈交付优先使用薄编排入口

- 同一名开发者承担产品、交互、前后端、测试和验收时，业务、跨栈、实现、验证或跨会话续作优先使用 `chinamate-fullstack-delivery` Skill 推导当前阶段和最短安全路径。
- 主 Agent作为控制面，按阶段或独立工作包签发`TaskContract`并创建最少必要的 fresh subagent；新合同使用fresh上下文，同一合同的`CorrectionContract`可复用原subagent。不得为了形式完整启动全部角色，也不得在适用specialist可用时由主Agent静默模拟非平凡角色交付。
- 主 Agent是合同唯一签发、验收与change根`handoffs/`持久化主体；subagent只返回`ResultContract`或`ReviewResult`payload，不得生成用户确认、自行派工或扩大权限。handoffs只保存执行快照，不得替代OpenSpec、Git、测试或`evidence.md`。
- 前后端仅在合同冻结、依赖满足且写入范围不冲突时并行；QA等待实现稳定，只读reviewer按适用性并行。简单任务可走fast path，能力不可用时明确`DEGRADED`或`BLOCKED`，不得伪造多Agent交付。
- 编排不能扩大用户授权；规格确认、Git 写操作、质量阻断与归档建议继续执行既有硬门禁。

## RULE-WF-006：可由用户解除的流程阻塞必须立即升级

- 当前计划中的必需步骤因缺少用户授权、审批或必须由用户作出的决策而无法继续，且用户响应可以直接解除阻塞时，必须在同一处理阶段使用正式审批机制申请最小必要授权或立即向用户请示。
- 请求必须说明被阻塞步骤、所需授权或决策、精确目标与影响范围、主要风险以及获批后的继续动作；需要用户决策时，必须提出清晰可回答的问题并说明不同选择的影响；一次授权不得扩大到当前任务范围外、其他仓库或后续操作。
- 已知需要授权或决策后，不得静默等待、转做无关工作、绕过权限、擅自改变目标或范围、降低质量门禁、跳过必需步骤，或把 `BLOCKED`、`NOT_RUN` 声明为完成。
- 现有授权内存在不改变目标、范围、质量门禁和外部影响的安全可验证等价路径时，应自主采用并继续；替代路径会改变交付结果或降低证据时，必须先请示。
- 用户拒绝、暂未响应，或外部故障无法由授权直接解除时，保护当前安全状态并记录阻塞步骤、已尝试路径和影响；继续穷尽现有授权内的安全诊断，不得重复发送无新信息的相同请求或伪造完成。
