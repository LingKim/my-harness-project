## ADDED Requirements

### Requirement: 可由用户解除的流程阻塞必须立即升级

当当前必需步骤因缺少用户授权、审批或必须由用户作出的决策而无法继续，且用户响应能够直接解除阻塞时，代理 MUST 在同一处理阶段立即通过正式审批机制申请授权或向用户请示。请求 MUST 说明被阻塞步骤、所需授权或决策、精确目标与影响范围、主要风险和获批后的继续动作。代理 MUST NOT 静默等待、绕过权限边界、擅自改变交付目标或范围、降低质量门禁、跳过必需步骤，或把未执行项声明为完成。

#### Scenario: 工具操作需要额外授权

- **WHEN** 当前必需命令或工具调用因 sandbox、文件系统、网络、Git、外部写入或其他审批边界无法继续
- **AND** 正式授权能够解除该阻塞
- **THEN** 代理必须立即使用对应审批机制请求最小必要授权
- **AND** 请求必须包含精确目标、用途、风险和获批后的继续动作
- **AND** 不得先跳过该步骤或等到最终报告才说明

#### Scenario: 必须由用户作出决策

- **WHEN** 缺少一个会实质改变目标、范围、质量、外部状态或实现方向的用户决定，导致当前必需步骤无法安全继续
- **THEN** 代理必须立即提出一个清晰、可回答的阻塞性问题并说明不同选择的影响
- **AND** 不得自行猜测用户决定或采用会改变交付结果的默认方案

#### Scenario: 现有授权内存在等价安全路径

- **WHEN** 当前方法失败，但现有授权范围内存在不改变目标、范围、质量门禁和外部影响的安全可验证替代路径
- **THEN** 代理可以自主采用该路径继续推进
- **AND** 不得仅因出现普通错误就要求额外授权或中断用户

#### Scenario: 替代路径会降低交付质量

- **WHEN** 可用替代路径会跳过测试、减少证据、改变实现或协议、缩小范围，或者产生不同的外部状态
- **THEN** 代理必须先向用户请示并说明取舍
- **AND** 未获确认不得把降级路径当作原目标已经完成

#### Scenario: 用户拒绝授权或暂未响应

- **WHEN** 用户拒绝所需授权、没有提供必须决策或暂未响应阻塞性请求
- **THEN** 代理必须保留当前安全状态，明确记录阻塞步骤、已尝试方案和影响
- **AND** 不得绕过权限、重复发送无新信息的相同请求或伪造完成结果

#### Scenario: 外部故障不能由用户授权解除

- **WHEN** 阻塞来自用户授权无法直接解除的第三方故障、依赖缺陷或环境不可用
- **THEN** 代理必须继续穷尽现有授权内的安全诊断和等价替代方案
- **AND** 只有确实无法继续时才报告真实 `BLOCKED`，不得把外部故障错误描述成授权问题
