## Context

当前根 `AGENTS.md` 已规定未经授权不得执行 Git 写入、外部写入和破坏性操作，工具层也会在沙箱权限不足时要求显式审批；但项目没有明确要求代理在“用户授权或决策可以解除当前阻塞”时必须立即升级。因此，代理可能只记录 `BLOCKED`、等待到最终报告才说明、用低质量替代方案绕过，或直接跳过必需步骤。

该约束属于跨仓库工作流治理：入口应在根 `AGENTS.md` 可见，稳定语义应集中在 `.codex/rules/workflow.md`，关键控制应登记到单人交付控制矩阵。入口只做路由和不可降低边界，不复制完整 Rule。

## Goals / Non-Goals

**Goals:**

- 在可由用户授权、审批或决策解除当前阻塞时，要求代理在同一处理阶段立即发起请求。
- 让请求说明阻塞步骤、所需授权/决策、影响范围和解除后继续执行的动作。
- 禁止静默等待、绕过权限、擅自降级目标或跳过必需验证。
- 保留代理在现有授权内安全自主解决问题的能力。

**Non-Goals:**

- 不扩大工具、Agent 或 sandbox 权限。
- 不要求对不影响当前路径的提醒、可自行修复的小问题或用户无法解决的外部故障反复请示。
- 不改变 destructive action、Git、外部写入和 OpenSpec 确认的既有授权边界。

## Decisions

### 1. 以“当前必需步骤被阻塞且用户可以解除”为唯一触发条件

只有同时满足以下条件才必须立即申请：当前计划中的必需步骤无法继续；原因是缺少用户授权、审批、凭据外的用户决策或受控外部动作许可；用户响应能够直接解除阻塞。这样可以覆盖沙箱升级、Git 写入、外部系统写入和关键方案选择，同时避免普通警告导致过度打断。

备选方案是遇到任何错误都请示用户，但这会把可自主诊断和修复的问题也升级，降低开发效率。

### 2. “立即”定义为不得先结束本轮、转做无关工作或降级完成声明

发现触发条件后，代理必须在同一处理阶段调用正式审批机制或发送一个精确、阻塞性的用户问题。允许先执行必要的只读定位以解析精确目标和风险，但不得在已知所需授权后继续大量无关工作、等到最终报告才提及，或把步骤标为跳过。

工具已经提供审批接口时直接使用该接口，不额外发送重复预告；需要产品/方案决策时用简短问题说明选择影响。

### 3. 请求必须最小、具体、可继续

请求至少说明：被阻塞的必需步骤、需要的具体授权或决策、精确目标/范围、主要风险，以及获批后将继续什么。不得索取超出当前任务的宽泛权限，也不得把一次授权扩大到后续操作或其他仓库。

### 4. 安全替代方案只在不改变交付结果时自主采用

如果现有授权范围内存在安全、可验证且不改变目标、范围、质量门禁或外部影响的替代路径，代理可以直接采用并继续。如果替代方案会跳过测试、降低证据、改变实现、扩大/缩小范围或产生不同外部状态，则必须先请示。

### 5. 用户拒绝或无法解除时保留真实阻塞

用户拒绝授权、未提供必须决策，或故障无法由用户授权解决时，代理必须保护当前状态、记录已尝试的安全路径和影响，明确报告 `BLOCKED` 或 `NOT_RUN`。不得绕过安全边界，也不得重复发送没有新信息的相同请求。

## Risks / Trade-offs

- [请求过多打断用户] → 仅在当前必需步骤被阻塞且用户响应可以直接解除时触发；可安全等价解决的问题继续自主处理。
- [请求过宽扩大权限] → 强制说明精确目标、范围和后续动作，一次授权不跨仓库或跨后续步骤复用。
- [为了不中断流程而绕过安全边界] → 明确“及时升级”不等于自行越权；拒绝或未获批时保持阻塞状态。
- [治理脚本只能检查文本存在] → 自动检查验证入口、Rule ID 和控制矩阵登记；具体时机与请求质量由 QA/Spec Review 结合实际日志审查。

## Migration Plan

1. 用户确认触发条件、立即时机、安全替代和拒绝处理边界。
2. 先增加治理失败夹具，再更新 Workflow Rule、根入口和控制矩阵使检查转绿。
3. 同步主规格并运行 Agent governance、Harness、OpenSpec strict validate 与 `git diff --check`。
4. 回滚时整体恢复新 Rule、入口路由、控制矩阵和检查；不涉及业务数据或运行时 migration。
