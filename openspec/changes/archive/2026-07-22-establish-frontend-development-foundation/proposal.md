## Why

当前前端只具备可运行的 Next.js 初始化基线，尚未形成 ChinaMate 业务页面共用的双语路由、全局页面框架、通用页面状态和浏览器验收能力；同时独立 TypeScript 检查会因 Vitest 全局类型缺失而失败。若直接进入账号、攻略、AI 或社区功能开发，这些横切能力会被各功能重复实现并带来路由、文案和测试返工，因此需要先建立最小且可验证的前端开发底座。

## What Changes

### 目标

- 修复并固化前端 TypeScript 类型检查门禁，使应用代码与测试代码都能被独立校验。
- 建立简体中文、英文两种语言的 App Router 路由、服务端文案字典和默认语言选择基础。
- 建立符合 PC 官网信息架构的全局布局、顶部导航、页脚、内容容器及最小首页壳层。
- 建立加载、空内容、错误、404、无权限和小屏降级等可复用页面状态。
- 建立面向 1920×1080 与 1440×900 的浏览器 E2E 基线，并把相关验证命令写入前端工程文档。

### 非目标

- 不实现账号注册、登录、会话、权限或旅行上下文。
- 不实现攻略、AI 助手、社区等业务数据请求和交互。
- 不提前引入全局状态管理、大型 UI 组件库、通用 API SDK 或业务表单框架。
- 不承诺低于 1280px 的完整移动端响应式体验，只提供明确且可用的基础降级。
- 不修改后端接口、数据库结构、根级环境编排或部署方案。

### 可衡量验收结果

- `pnpm lint`、`pnpm typecheck` 和 `pnpm test` 全部通过。
- 中文与英文 URL 均可直接访问，未知语言返回 404，根路径按已定义规则进入受支持语言。
- 语言切换保留当前页面路径；本变更没有业务筛选和表单，因此不虚构对应状态恢复逻辑。
- 1920×1080 与 1440×900 浏览器检查不存在横向溢出，首页首屏可见产品定位、AI 提问入口和主要行动按钮。
- E2E 自动覆盖根路径语言处理、双语导航、语言切换、404 和基础小屏降级。

## Capabilities

### New Capabilities

- `frontend-development-foundation`: 定义 ChinaMate 前端类型门禁、双语路由与文案、全局页面框架、通用页面状态和浏览器 E2E 基线。

### Modified Capabilities

无。

## Impact

- 主要影响 `frontend/` submodule 中的脚本、TypeScript/Vitest 配置、App Router 目录、样式、公共组件、双语资源、单元测试、E2E 配置和前端 README，并同步更新根级 `scripts/check-harness.sh` 对前端测试入口与门禁脚本的检查。
- 主仓库新增本 OpenSpec change，并在实现完成、前端提交推送后更新 `frontend` gitlink 和跨仓库计划状态。
- 预计新增少量直接服务于 E2E 或语言协商的开发依赖；具体依赖必须在设计阶段论证，不能仅因通用建议引入。
- 主要风险是双语 URL 与后续认证返回路径不兼容、根级 Client Provider 扩大客户端包、PC 栅格与英文长文案产生溢出；通过服务端优先、最小客户端边界、稳定 locale 契约和双视口 E2E 降低风险。
